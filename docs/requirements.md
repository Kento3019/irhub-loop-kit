# IRハブ 要件定義

ESP32でエアコンを赤外線で操作する自作ハブ（照明は対象外。1章を参照）。スマホのブラウザから操作する。

- 版：v0.5（2026-09-28）フェーズ1・2の結果を反映（プロトコル・値の範囲・初期値の確定、温湿度センサーをAHT25に変更、配線v2）
- 前版：v0.4（2026-09-26）照明のリモコンが電波式と判明したため、照明を対象から外す
- 状態の書き方：**決定**＝確定済み／**仮**＝このまま進めてよいが変わりうる／**未決**＝決まるまで該当部分は作らない

---

## 1. 目的とスコープ

### 目的
- SwitchBotハブ相当の機能を、市販品より安く自作する（部品代の目安：¥5,000前後）
- 電子工作の学習を兼ねる

### 対象機器（決定）
| 機器 | リモコン | 方式 |
|---|---|---|
| エアコン | 日立 RAS-AJ22C(W)（白くまくん AJシリーズ、2014年製）／リモコンはオーム電機 OAR-N9（汎用） | 赤外線 |
| ~~シーリング照明~~ | KOM OCH-006(K)/OCH-008(K)、6ボタン | **電波式（赤外線ではない）→ 対象外** |

**プロトコル（決定）**：IRremoteESP8266 の `HITACHI_AC296`。フェーズ1でOAR-N9の信号を受信して判明し、フェーズ2で `IRac` から送った運転をエアコンが受け付けた。`IRac` で送れるのは運転・モード・温度・風量

**照明について（決定）**：リモコンが電波式だった（リモコンの先を手で覆っても照明が反応した）。赤外線では操作できない。部屋は借りている部屋（マンスリーマンション）なので、リモコンや照明の分解・改造はしない。技適のない無線モジュールで電波を出すこともしない。照明は今回のスコープから外す。将来の候補：リモコンを壊さずにサーボで「切/入」ボタンを押す機構。

### やらないこと（決定）
- スマートスピーカー連携
- 通知
- 室温に応じた自動運転
- 照明の操作（電波式のため）。将来の候補はサーボでリモコンのボタンを押す機構
- 借りている部屋の備品（リモコン・照明・エアコン）の分解・改造
- 純正リモコンで操作された状態との同期
- スケジュールや状態の永続化（ESP32のフラッシュへの保存）
- プログラムのWi-Fi経由の更新（OTA）
- クラウドサービスの利用

## 2. 機能要件

### F1 エアコン操作（決定）
リモコン（OAR-N9）でできる操作をすべて画面から行える。

| 項目 | 値 |
|---|---|
| 運転 | 運転／停止 |
| モード | 自動・冷房・除湿・暖房 |
| 温度 | ▲▼で1℃刻み。16〜30℃（自動は温度指定なし） |
| 風量 | 自動・静音・弱・中・強の5段階 |
| 風向 上下・左右 | 作らない（`HITACHI_AC296` の `IRac` で送れないため） |
| 本体タイマー 入／切 | 非対応。 F4 スケジュールで代替し、この項目は作らない |

**送り方**：エアコンの信号は、ボタン1つ分ではなく「運転・モード・温度・風量」の状態一式を毎回まとめて送る。画面で1項目を変えたときも、状態一式を送る。
**停止中**：停止中は運転の入切を含まない変更を送らない


### F2 初期設定（決定）
起動直後と、モードを切り替えたときに使う値。モードごとに最後に使った設定を持ち、再起動で下の初期値に戻る。値の置き場所は `lib/core/src/ac_state.cpp` の `kInitialSettings` の1か所。

| モード | 温度 | 風量 |
|---|---|---|
| 冷房 | 26℃ | 自動 |
| 暖房 | 22℃ | 自動 |
| 除湿 | 26℃ | 自動 |
| 自動 | 温度指定なし | 自動 |

暖房22℃は、エアコンに設定温度の表示がなく動作の違いを見分けられなかったため、一般的な目安（環境省の冬の室温目安20℃、家庭の暖房設定の平均23.1℃）を参考に決めた（D2）。

### F3 照明操作（対象外）
照明のリモコンが電波式のため、今回は作らない。画面とAPIにも照明の項目を入れない。

### F4 スケジュール（決定）
- 画面から登録・編集・削除できる
- 1件の中身：時刻、曜日（複数選択）、対象と操作（エアコン：運転＋モード＋温度など／エアコン停止）、有効・無効
- 件数の上限：仮に10件
- 再起動で消えてよい
- **エクスポート／インポート**：スケジュール一覧をJSONファイルとしてスマホに保存でき、そのファイルを読み込んで戻せる。再起動後に手で戻すための機能（ゲームのセーブデータのような使い方）
- 時刻はNTPで取得した日本時間（JST）

### F5 室温・湿度の表示（決定）
- 温湿度センサー（AHT25。DHT20と同じメーカーの互換品）の値を画面に表示する
- 更新間隔：仮に30秒
- 履歴は持たない

### F6 外出先からの操作（決定）
- 常時起動している自宅PC（Windows 11 Home）を踏み台にし、Tailscale経由でESP32の画面に入る
- 方式：PCをTailscaleの**サブネットルーター**にする（WindowsはTailscaleのサブネットルーターに対応している）
- 公開する範囲はESP32の1台だけにする：`tailscale set --advertise-routes=<ESP32のIP>/32`（管理者権限で実行）。家のLAN全体（/24）は公開しない
- Tailscaleの管理画面で、そのルートを承認する
- PCの設定：スリープしない。Tailscaleの「Run unattended」を有効にする（Windowsからサインアウトしている間も接続を保つため）
- スマホは外出先から `http://<ESP32のIP>/` を開けば、家の中と同じ画面が使える。ESP32側で特別な対応は要らない
- 前提：ESP32のIPが固定されていること（非機能要件のIPアドレスの項）

## 3. 非機能要件

| 分類 | 要件 | 状態 |
|---|---|---|
| 利用者 | 自分のみ。LAN内なら誰でも操作できる | 決定 |
| 認証 | LAN内は認証なし | 決定 |
| 可用性 | Wi-Fiが切れたら再接続を最大3回（計30秒程度）試み、すべて失敗したら再起動して再接続をやり直す | 決定 |
| 状態の保持 | 稼働中だけメモリに持つ。再起動で初期値に戻る | 決定 |
| 起動時の動作 | 起動・再起動のときにエアコンへ信号を送らない（停電から戻った瞬間に勝手に動かないように） | 決定案 |
| 時刻 | NTPで取得、JST。取得できない間はスケジュールを実行せず、画面に警告を出す | 仮 |
| 応答 | 画面のボタンを押してから赤外線を送るまで1秒以内 | 仮 |
| 保守 | プログラムの書き込みはUSB接続 | 決定 |
| 秘密情報 | Wi-FiのSSIDとパスワードはコードに直接書かず、Gitに含めない別ファイル（`include/secrets.h` を `.gitignore`）に置く | 決定案 |
| IPアドレス | ルーターのDHCP予約で固定する。ルーターを触れない場合はESP32側で、ルーターの自動割り当て範囲の外に固定する | 仮 |
| 設置 | エアコンの受光部が見え、USBで給電でき、Wi-Fiが届く室内 | 決定 |

## 4. 画面（仮）

- スマホの縦画面向けの1ページ
- 画面の構成はSwitchBotアプリの操作画面を参考にする：機器ごとのカード、エアコンは温度を大きく表示して左右に−／＋、モードと風量はアイコン付きのボタン
- 参考にするのは配置と操作の考え方だけ。SwitchBotのロゴ・アイコン・名称・配色は使わない
- 構成：
  1. 上部：室温・湿度、時刻、NTPの状態
  2. エアコンカード：運転／停止、モード、温度、風量
  4. スケジュール：一覧、追加・編集、エクスポート／インポート
- HTML＋CSS＋JSを1ファイルにまとめる。Reactやnpmなどのビルドツールは使わない
- HTMLはファームウェアに文字列として埋め込み、`GET /` で返す

## 5. API（仮）

エアコンは、IRremoteESP8266の共通インターフェース（`IRac`）の状態の形に合わせる。プロトコルが決まる前でも形は決められる。値の範囲と選択肢だけ、受信結果で確定する。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/` | 操作画面のHTML |
| GET | `/api/status` | エアコンの現在の設定、室温・湿度、時刻、NTPの状態 |
| POST | `/api/ac` | エアコンの設定を変更して送信。送った項目だけ変更し、状態一式を送る |
| GET | `/api/schedules` | スケジュール一覧 |
| PUT | `/api/schedules` | スケジュール一覧をまとめて置き換える |
| GET | `/api/schedules/export` | スケジュール一覧をJSONファイルとして返す（ダウンロード） |
| POST | `/api/schedules/import` | JSONファイルの内容でスケジュール一覧を置き換える |

例：
```json
// POST /api/ac
{ "power": true, "mode": "cool", "temp": 26, "fan": "auto" }

// エクスポートファイル
{ "version": 1, "exportedAt": "2026-09-25T20:00:00+09:00",
  "schedules": [ { "id": 1, "enabled": true, "time": "07:00", "days": ["mon","tue","wed","thu","fri"],
                   "target": "ac", "action": { "power": true, "mode": "heat", "temp": 20 } } ] }
```
エラー時は HTTP 400 と `{ "error": "理由" }` を返す（例：温度が範囲外、JSONの形式が違う）。

## 6. ハードウェアの前提（決定）

### 部品（秋月電子通商）
| 部品 | 販売コード | 用途 |
|---|---|---|
| ESP32-DevKitC-VE（ESP32-WROVER-E、技適 211-200403） | 115674 | 本体 |
| ブレッドボード 6穴版 EIC-3901 | 112366 | 配線台 |
| 赤外線リモコン受信モジュール OSRB38C9AA | 104659 | リモコン信号の読み取り（フェーズ1のみ。配線v2では外した） |
| 5mm赤外線LED 940nm OSI5FU5111C-40 ×2 | 103261 | 送信。2個を直列につないで使う |
| トランジスター 2SC1815 | 117089 | LEDの駆動 |
| 抵抗 100Ω ×2 ／ 1kΩ ×1 ／ 10kΩ ×2 | 125101／125102／125103 | LED電流（100Ω×2を並列で50Ω）／ベース／I2Cプルアップ |
| 温湿度センサー AHT25（付属ケーブルでブレッドボードへ） | 116731 | 室温・湿度。DHT20（116732）が売り切れのため変更 |
| 積層セラミックコンデンサー 0.1µF | 113582 | AHT25の電源安定 |
| ジャンパーワイヤ（単線14種類×5本）、USBケーブル A-microB | 102315／107607 | 配線・給電 |

### ピン割り当て
| ピン | 接続先 | 備考 |
|---|---|---|
| IO23 | 1kΩ → 2SC1815のベース | 赤外線送信。配線v2でIO4から変更（K行の1本で右の空きへ出せるため） |
| IO14 | （未接続） | フェーズ1の受信で使用。プロトコル確定のため配線v2では外した |
| IO21 | AHT25 SDA | I2C。10kΩで3.3Vへプルアップ |
| IO22 | AHT25 SCL | I2C。10kΩで3.3Vへプルアップ |
| 3V3 | ＋レール → AHT25 VDD、10kΩ×2、0.1µF | ＋レールは3.3V専用 |
| 5V | 100Ω×2並列（50Ω）→ 赤外線LED 2個直列 → 2SC1815 | 5V系はLEDだけ。レールには入れない |
| GND | −レール経由で全部品共通 | |

配線の詳細（穴の位置）は「IRハブ配線 v2」の資料を正とする。

### 電気的な制約
- ESP32のピンは3.3Vまで。ピンにつながる部品（AHT25）は3.3Vで動かす
- 赤外線LED：5V − LED 1.4V×2 − トランジスタ 0.2V = 抵抗に2.0V → 2.0V ÷ 50Ω = 約40mA（2個とも同じ電流）。抵抗1本あたり約0.04W（上限0.25W）
- 5V電源でLEDを直列にできるのは2個まで（3個だと抵抗に残る電圧が約0.6Vになり、電流が安定しない）
- さらに届く距離を伸ばす場合：50Ω→22Ω（約90mA）とベース1kΩ→470Ω。部品の買い足しが必要

## 7. 技術的な制約（決定）

- 開発環境：PlatformIO（VS Code）
- プラットフォーム：PlatformIO公式の `espressif32`（Arduino core 2.x系）。3.x系（pioarduino）は、IRremoteESP8266がコンパイルエラーになる問題があったため使わない
- `platformio.ini` に `monitor_speed = 115200` を書く
- 赤外線：IRremoteESP8266。エアコンは `IRac` の共通インターフェースを優先して使う
- 温湿度：AHT25（I2Cアドレス 0x38、DHT20用ライブラリで読める）
- Webサーバ：Arduino core の `WebServer`（ESPAsyncWebServer は使わない。仮）

## 8. 作る順番と完成の判定

| フェーズ | 内容 | 完成の判定 |
|---|---|---|
| 0 | ESP32単体の動作確認 | シリアルモニタに1秒ごとに文字が出る |
| 1 | 赤外線の受信と解析 | エアコンのリモコンで、メーカー名（プロトコル）と「Mode・Temp」などが表示される |
| 2 | 赤外線の送信 | ESP32から、エアコンの運転・停止・温度変更が動く。設置場所から届く |
| 3 | 温湿度 | 室温と湿度がシリアルに出て、室温計と大きくずれない |
| 4 | 画面とAPI | スマホで画面を開き、F1・F5が使える |
| 5 | スケジュール | 登録した時刻に動く。エクスポートしたファイルを、再起動後にインポートして元に戻せる |
| 6 | 外出先から | Wi-Fiを切ったスマホ（モバイル回線）から、Tailscale経由で画面を開いて操作できる |
